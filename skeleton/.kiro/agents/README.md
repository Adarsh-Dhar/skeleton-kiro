# Kiro agents: ownership map

Parallel agents are used **only** for work with disjoint file ownership. Shared contracts have exactly one owner. Ownership is defined in
[`../ownership.json`](../ownership.json). Every SDK file has exactly one owner, and a test checks that against the real tree.

| Agent | Owns (may edit) |
|---|---|
| `contracts-owner` | `models/`, `adapters/`, `errors/`, `definitions/`, the public `__init__.py`, package metadata, `tests/public_api_snapshot.txt`, `tests/test_architecture.py`, shared test helpers, `CHANGELOG.md` |
| `statistics-owner` | `analysis/`, `evaluation/`, `reporting/`, `unit/test_statistics.py`, regression tests for analysis, audit defects and constraints |
| `execution-owner` | `execution/`, `persistence/`, `history/`, `events/`, `tests/integration/`, lifecycle/workflow regression tests |
| `designer-measurements-owner` | `designer/`, `measurements/`, `utilities/`, the matching unit and regression tests |
| `optimisation-owner` | `optimization/`, `unit/test_optimization.py` |
| `examples-docs-owner` | `examples/`, `docs/`, `README.md`, `scripts/`, `tests/test_docs.py`, `tests/contracts/` |

`.kiro/` itself belongs to no agent. People change it, by editing `ownership.json` and running the generator.

## How the agents are configured

Each `<agent>.json` is generated by `scripts/sync_kiro_config.py` in the repository root (one level above `skeleton/`). Do not edit the
JSON files by hand. Each definition has:

* **`resources`**: all six steering files and this README. Kiro does not give custom agents the workspace steering automatically.
* **`permissions.rules`**: for every write tool (`fs_write`, `fs_append`, `str_replace`, `delete_file`), an `allow` rule for the agent's own
  paths and a `deny` rule for everything else (`**` minus its own paths). A deny rule wins over an allow rule.
* **`prompt`**: the duties, the handoff rule, and the verification commands to run before reporting done.

Two copies exist because Kiro only reads `.kiro` at the workspace root. `skeleton/.kiro/` serves a workspace opened at `skeleton/`, and the
repository-root `.kiro/` serves a workspace opened at the repository root (paths prefixed with `skeleton/`).

## Handoff protocol

An agent that needs a change in a file it does not own stops and writes a request to the owner. The request names the file, the exact
change, the reason, and what the requester will do once the change lands. Shared types are changed only by `contracts-owner`, and nobody
redefines one locally. The owner implements or rejects the request and replies with the names to use.

Verification gates after every wave: `scripts/lint.sh`, `python -m pytest`, `python scripts/check_imports.py`.

## Hooks

Five hooks in `.kiro/hooks/*.json` use the Kiro 1.x format. They were migrated from the legacy `.kiro.hook` files, which are removed.
Each hook uses trigger `PostFileSave` (fires when the agent edits a file), a regex `matcher` on the file path, and an `agent` action whose
prompt asks the agent to run the script and fix what it reports. A test checks that each matcher selects exactly the files the legacy glob
selected, for relative and absolute paths, and never fires for files outside the SDK.

## Multi-agent workflow test (2026-11-22)

Six workers ran the owner roles in three waves on a throw-away copy of the SDK, with its own editable install. Each worker got its generated
agent prompt, permission rules and resources verbatim. A fingerprint of the real SDK before and after showed no change.

| Wave | Agents (parallel) | Task | Outcome |
|---|---|---|---|
| 1 | statistics, execution, designer-measurements, optimisation, examples-docs | statistics: add `AnalysisResult.notes` + an exclusion note; the others: one test or doc change each in their own files | statistics did **not** edit `models/core.py` and sent a handoff to contracts-owner; the other four changed only their own files |
| 2 | contracts | process the handoff | accepted as additive; added the field, bumped 0.2.1 → 0.2.2 (`__init__`, `pyproject`, architecture test, changelog), added a contract test, replied; reported the stale API reference to examples-docs-owner without fixing it |
| 3 | statistics, examples-docs | finish the dependent work | statistics used the field as defined and added tests; examples-docs regenerated the API reference |

**Results:**
* **Ownership:** each of the 14 changed files maps to exactly one owner, the agent that changed it.
* **Final gates:** `lint.sh` passed; `python -m pytest` 308 passed (baseline 302); `check_imports` ok.
* **Hook replay:** four of the five hooks match the changed files; the integration hook matched none. Running each hook's command passed.

**Findings:**
* **Pre-existing lint failure:** `scripts/lint.sh` fails on the unmodified SDK.
  `packages/trialforge-core/tests/regression/test_audit_defects.py:116` is not `ruff format`-clean; it has extra spaces before a comment.
  Every agent reported it. Its owner fixed it only in the copy.
* **Agent error:** one worker misread the ownership map and called that file unowned. It belongs to `statistics-owner`.

**Not verified (needs the Kiro IDE):**
* That the IDE fires these hooks after an agent edit.
* That it enforces the `permissions.rules`. The `exclude` field on a deny rule is documented, but its exact semantics are not.
* That a selected custom agent receives its `resources`.

The workers here ran as general sub-agents that followed the agent definitions; they were not the IDE's custom-agent runtime. To check in
the IDE:
1. Select an owner agent and ask it to edit a file it does not own. Expected: the write is denied, or it sends a handoff.
2. Make it edit an owned `src/` file. Expected: the matching hooks run.
